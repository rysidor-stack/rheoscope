## 0. The wall, in brief

**Capability is a pure function of a session's boot-time assembled context, and the credentialed surface is mechanical, not agentic.** A session whose boot context carries any untrusted origin is **granted no credential or egress tool** (they are *absent from the toolbox*, not "forbidden"); a credentialed session is **structurally unable to ingest new untrusted content after boot**; and **no LLM ever holds both credentials and untrusted-derived content** — credentialed actions are performed by audited deterministic executors over already-promoted artifacts (§8, the strict default). So there is nothing to police at runtime, and the unbounded LLM surface is kept out of the credentialed path entirely.

The harness decides this **at tool-grant, before the agent runs, where the agent has no vote.**

---

## 1. What moves, and why the boundary is now winnable

The frozen §9 enforced co-residency as a **data-flow gate inside packet assembly** (refuse a tainted packet to a credentialed profile *unless attested*). Three cross-vendor passes broke it at the **exception seam** — never the core (F8/F9/F10 held all three times). The pivot changed the question from *"make co-residence safe"* to *"make co-residence impossible."*

The v1.0 draft of this spec moved enforcement to tool-grant but kept reaching into the **runtime** (mid-session revoke, fenced turns) and leaned on a **lineage tracker the frozen source does not provide.** The rung-1 pass (§14) showed both are unavailable: the harness's own doctrine says its gates *"live in preflight/sensors, **not** PreToolUse hooks"* (`test-plan:20`) and *"runtime interception is a capability variable, not physics"* (`inner-ring:39`).

So v1.1 founds the whole model on the one surface the harness **can** make deterministic — **boot-time tool-grant** — and removes every dependency on the surface it **cannot** (runtime interception):

- **Capability = f(boot-time assembled-context origin).** Computed once, before the agent runs, from the origin of every byte in the boot context, over an **audited allowlist** (§5). This is just tool-grant; the harness already does it.
- **Credentialed sessions are boot-immutable w.r.t. untrusted content.** Their grant excludes every tool that could pull new untrusted bytes (fetch, paste, arbitrary read); they read only first-party-trusted corpus (§4). Nothing untrusted can enter after boot ⇒ **no race, nothing to intercept** ⇒ the hardest v1.0 finding (the mid-session timing race) is *dissolved*, not patched.
- **The trusted surface shrinks** to one boot-time decision + a schema validator + a path/tool allowlist — a few hundred lines, **fixture-testable exhaustively** for the *decision* (the inputs are completeness-reviewed; §12).

This is the harness's own doctrine made literal — *"a boundary, not a hope; architecture, not discipline"* — enforced by **which tools exist in the session at boot**, not by an instruction the attacked agent is asked to obey, and not by a runtime monitor the harness can't build.

## 2. TCB boundary — what must be correct vs. what is assumed hostile

| In the TCB (small · deterministic · fixture-tested · runs pre-agent in the harness) | Outside the TCB (assumed fully compromised) |
|---|---|
| the **origin-tagger** (reads §4 canonical origin per context item) | the agent's reasoning and **any** LLM output |
| the **ingest-tagger** (stamps fetched/tool-returned/pasted bytes at intake, §4) | the optional **injection scanner** |
| the **lineage propagator** (computes boot-context `origin_max`, F9) | the **typed-record projector** (the research→action extraction, §8 — attackable; can only mis-*value*, never inject, see §8) |
| the **capability classifier over the audited allowlist** (§5) | **every orchestrator-supplied descriptor string/flag** (never believed) |
| the **grant decision** (`requested ∩ SAFE`, boot-time) | any tool the agent invokes; any interpreter/shell |
| the **schema validator** for the §8 bridge record (no free-text fields; vocabulary-conformant) | the content/values inside a valid typed record (data, never instruction-to-the-TCB) |
| the **fetch mediator** (destination-allowlist + intake tagging, §7) | |
| the **attestation/signature verifier** (if a sandbox is used; F17 discipline) | |

Two non-negotiable principles:

- **(P-A) The attacked component never enforces the rule.** The agent is never the thing that decides its own capabilities; the decision is upstream, in code the agent cannot call into or alter.
- **(P-B) The decision derives only from runtime-evidenced facts, never orchestrator-supplied strings.** Capability is read from the *actual* environment and the *audited allowlist*; origin from the §4 registration record; substrate identity from invocation metadata (F17/F18). The forged-green-light FATAL is a *category* this principle closes.

## 3. Inputs the TCB reads (at boot)

All inputs are runtime-evidenced (P-B). The orchestrator's *requested* capability set is an input but is a **request, not a grant**.

1. **Requested capability set** — what the session is asked to have.
2. **The boot-time assembled context** — every event/view/note/record in the context, each carrying its canonical `origin` from the §4 append-only registration record, **plus** any fetched/tool-returned/pasted bytes that were folded in, each carrying an origin row from the ingest-tagger (§4). Default-deny: any byte with no origin row is `unknown` ⇒ untrusted.
3. **The audited tool & path allowlist** (§5) — the closed set of tools/paths proven not to confer credential or egress capability, with their parameter-bounded contracts.
4. **The effective runtime environment** — present secrets, mounted credential files, configured remotes/endpoints — read from the substrate (used to validate the allowlist against reality, fail-dangerous on mismatch).
5. **Invocation metadata** — for substrate identity wherever an attestation is in play (F17/F18).

## 4. Origin-tagging (reuse §4; close the ingest gap; split corpus; honest backfill)

The §4 origin machinery and F9 propagation stay as machine logic; this scope **extends F9's `origin_max` from view-assembly to the boot context** and reads it as the gate input. The rung-1 pass (§14, findings A/E/F) requires three additions:

- **Origin classes (§4):** `human | corpus | vendor-ref | external-scrape | unknown`, with a new co-residency-permitted derivative class `typed-derived` (§8). Default-deny: missing/unparseable/unrecorded `origin` ⇒ `unknown` ⇒ untrusted (`unknown ≥ external-scrape`).
- **Trusted set := `{human, corpus-first-party}`** (the **corpus split**, finding E). The frozen §9 inheritance `{human, corpus}` was set for the data-flow model; under capability-isolation a corpus repo can carry vendored/third-party/scraped bytes, and SHA-pinning guarantees *immutability, not trustworthiness*. So **`corpus` is partitioned**: paths under a positively-attested first-party allowlist are trusted; vendored/third-party/scraped corpus is `vendor-ref`/`external-scrape` and untrusted. (A *tightening* of the frozen rule, carried as this dated sibling — never an edit; the safe direction.) **First-party attestation is provenance-based, not path-based (rung-2 finding):** an attested *path* guarantees location, not authorship — a merged external PR, a too-broadly-scoped vendored subdir, or a file a tainted earlier session wrote into a first-party path would all inherit trust. So `corpus-first-party` requires **change-controlled provenance** — **an attested blob-SHA manifest is the load-bearing form**; commit-authorship history alone is **not sufficient** (rung-3: a squash/rebase merge of an external PR rewrites authorship to the first-party merger, so "whole git history first-party-authored" passes on external content). Any blob absent from the attested manifest is `unknown`, however it entered a first-party path. **The manifest is signer-verified against a trust root pinned *outside* the mutable workspace (rung-4)** — never workspace-local, never orchestrator-supplied (P-B); absence or verification failure collapses the covered blobs to `unknown`. And **the ingest-tagger wins over path-trust**: any byte under an attested path whose own derivation is `unknown`/`external-scrape` stays untrusted (fail closed).
- **Ingest-tagging (finding A — the only true lineage gap).** Cross-session origin already propagates at *artifact* granularity via F9 + the registration record; the gap is that **fetched / tool-returned / pasted bytes are not events and carry no origin row.** Fix: the **fetch mediator and any tool-return path stamp ingested bytes `external-scrape` (or `unknown`) at intake, before the agent sees them**, inside the (credential-free) session that pulls them. Existing F9 then propagates the taint into anything that session authors. No runtime lineage tracker is required — the tagging happens at intake, and enforcement reads it at the *next* session's boot.
- **System projections are a named ingress path (rung-1b finding, verified).** The frozen `ACC-3` origin check **excludes** the `INDEX/HEALTH/REVIEW` projections (`memory-engine-v3-test-plan.md:79,155` — the `NEVER_SOURCE_TARGETS` regex), so a projection can carry untrusted-derived summary text with **no `origin_max`**. A tainted session could write a projection that a later credentialed session reads as clean. Fix: any projection a credentialed boot context could read MUST be origin-bearing (default-deny `unknown` if it lacks a derivation block) — equivalently, a credentialed session may not ingest an untagged projection. The ingest enumeration (C2) must include every projection path — and **the set must be closed and explicit** (rung-3): not only `INDEX/HEALTH/REVIEW` but `SESSION-BRIEFING/FLIGHTDECK/CATALOG` and any future projection; an unlisted projection defaults to ingestible-and-untagged, the exact gap. **A credentialed boot may NOT read an inner-ring judgment-checkpoint** (rung-3): a checkpoint's `origin_max` is *statistically* minted (the inner-ring's own conservation is "statistical … never an invariant", `inner-ring:135-139`), so consuming it as a runtime-evidenced fact violates P-B — credentialed work consumes only executor-promoted artifacts, never a working-summary. **This is one build-generated registry** consumed by both projection producers and boot-context assembly, with a `--self-test` that **fails on any projection path outside it** (rung-4: a hand-maintained list drifts — a future projection reopens the hole simply by existing; solve it mechanically).
- **Boot-context rule (the gate input):** `trusted(session) := origin_max(boot context) ∈ {human, corpus-first-party}`, computed over **every** context item including ingest-tagged bytes and any §8 bridge records (which are `typed-derived`, handled specially in §6/§8).
- **Backfill honesty for *all* trusted classes (finding F; extends DA-11).** No time-based upgrade to *any* trusted class. Auto-`human` only for operator-authored decision files with a receipt; auto-`corpus-first-party` only for bytes whose source is a positively-evidenced first-party corpus path. Any ambiguity **fails closed to `unknown`**, never to a trusted class — a wrong `corpus` mint blinds the gate exactly as a wrong `human` mint does.

## 5. The SAFE allowlist + capability classifier (DA-4 — decidable, default-deny)

The rung-1 pass (§14, finding D) showed "effective capability" cannot be *derived* for an open, data-parameterized tool set ("does any reachable composition of this tool's inputs touch a secret or a socket?" is undecidable). So SAFE is not a computed analysis — it is an **explicit, audited allowlist**:

- **`SAFE` is a closed allowlist of audited tools**, each with a **parameter-bounded contract** proven to have *no* path-, URL-, or interpreter-typed input and *no* credential-read or outbound channel. A tool is SAFE **iff it is on the allowlist**; everything else is dangerous.
- **`credentialed` / `egress_capable`** are then decidable: a tool is credentialed/egress-capable iff it is *not* on the SAFE allowlist (or is on a credential/egress allowlist). **Interpreters and shells are never SAFE** (they can reach any secret/socket the process can) — a research session is therefore **shell-less**, or uses a separately-specified constrained-interpreter contract (deferred; not assumed).
- **Fail-dangerous, one direction (the wording fixed in v1.0, kept):** *if a capability is not proven absent **by construction of the allowlist**, it is present.* "Prove absent" = "on the audited SAFE allowlist." Unknown / newly-attached / unclassified ⇒ **dangerous** (credentialed + egress-capable). There is **no** "defaults to no-creds" clause anywhere.
- **Allowlist-vs-reality check (P-B):** at boot the TCB validates that the granted tools match the audited allowlist and that the actual environment carries no capability the allowlist did not account for (an unexpected mounted secret, an attached endpoint) — mismatch ⇒ treat as dangerous.
- **SAFE is per-pipeline, not just per-tool (rung-2 finding).** Two individually-SAFE tools can *compose* into a channel: a SAFE "write data" tool plus a SAFE "render projection" tool can stage attacker-chosen bytes into a path a later credentialed boot reads as trusted. Auditing tools in isolation misses this. So: either the **credentialed-session read-set (§6) and SAFE-tool output paths are disjoint by construction**, or **every byte on a credentialed read path is ingest-tagged regardless of which SAFE tool wrote it** (the ingest-tagger, §4, wins over "a SAFE tool wrote it"). A SAFE tool's *output is still origin-bearing data*, never trusted-by-authorship.

Both unknowns point the same way: **unknown origin ⇒ untrusted; un-allowlisted capability ⇒ dangerous.**

## 6. The grant decision (the wall — boot-time)

Computed by the harness **before the agent runs**:

```
SAFE             := the audited tool/path allowlist (§5)
trusted(session) := origin_max(boot context) ∈ {human, corpus-first-party}      # §4, boot-wide
                    treating typed-derived bridge records per §8 (non-injective ⇒ co-residency-permitted)

if not trusted(session):
    grant := requested ∩ SAFE          # credential + egress tools ABSENT, not "denied"
else:
    grant := requested ∩ allowed       # normal least-privilege; PLUS the credentialed-session rule below
```

- **Intersection, not annotation.** There is no reachable path to excluded tools (no shell, no interpreter with net) because SAFE is an audited allowlist of capability-bounded tools.
- **The credentialed-session immutability rule (replaces v1.0 §8's runtime interception).** A session granted credential/egress tools is **also denied every tool that could ingest new untrusted content** — no web fetch, no paste, no arbitrary file read; its corpus reads are confined to the **first-party-attested path allowlist** (§4/§5). Its boot context is fixed and all-trusted, and it **cannot pull untrusted bytes during its life**. Therefore there is no mid-session taint ingress to intercept — the property is enforced by *toolset absence at boot*, which the harness can do, not by a runtime monitor, which it cannot.
- **The credentialed surface is mechanical, not agentic (strict default; §8).** Preferentially a credentialed session is an **audited deterministic executor, not an LLM** — so no LLM holds credentials + untrusted-derived content at all. An LLM may be credentialed only if it holds *no* untrusted-derived content (or via the gated §8 relaxation). The means to ingest untrusted content is absent from any credentialed grant, enforced at boot.
- **The security claim:** a fully-injected research session causes no exfiltration (no credential/egress capability granted); a credentialed action session cannot be hijacked by fresh untrusted content (it can't ingest any) and can only hold untrusted-derived data in the non-injective §8 form. The wall holds **regardless of content**, decided **entirely at boot.**
- **Work splits by capability** (the brief's point): **research** sessions carry untrusted content, hold no credentials, fetch freely (§7); **action** sessions hold credentials, act on already-trusted artifacts + §8 bridge records, and cannot ingest untrusted content. The hop between them is §8.

## 7. Research sessions (credential-free; fetch freely; tagged at intake)

A research session legitimately needs **outbound fetch** to scrape. That is safe **because it is credential-free**: a fully-injected research agent has nothing secret to read and no private channel that matters.

- **Credential-free by grant** (§6): no secret-read, no push, no credentialed tool — so post-boot fetching is harmless (there is no secret for a smuggled-URL / DNS / timing channel to carry).
- **Fetch through the harness-mediated fetch mediator** (a TCB component): a destination-allowlist contract bounds outbound; and — critically — the mediator **stamps every fetched response `external-scrape` at intake** (§4 ingest-tagging) so the taint propagates by F9 into anything the session authors.
- **Reads of untrusted content are fine here** (the session has no credentials to lose). The "no untrusted ingestion" rule is a property of **credentialed** sessions only (§6), not research sessions.
- **The sandbox's repurposed role:** in the old model the sandbox gated a (now-deleted) tainted→credentialed exception. Here it bounds the research session's outbound; until a runtime-evidenced, signed, fail-closed sandbox exists (deferred per frozen §16 / ADR #5), the conservative rule holds — a research session's only outbound is the mediated fetch tool.

## 8. The research → action handoff — strict default (option A); typed bridge gated

A credentialed action must be informed by research, yet no LLM may hold credentials + untrusted-derived content. The operator chose (2026-06-16) the **strict, fully-automated** posture: **the credentialed surface is mechanical, not agentic.** The co-residency question (can untrusted-derived content sit in a credentialed session without a *hijack* path) is kept separate from the correctness question (is the derived artifact *true/safe* — a Pillar-3 verify-then-promote question); conflating them was a v1.0/v1.1 error.

### 8a. Primary path (default, enforced)

- **LLM judgment over untrusted-derived content** — research, analysis, drafting, **and the verification of derived artifacts** — runs in **credential-free** sessions (no creds; no egress beyond the mediated fetch, §7).
- **The credentialed action is performed by an audited deterministic executor, not an LLM.** It consumes a typed plan/artifact, and its **action-specific guards must bound the blast radius assuming the artifact is attacker-controlled** (see the promotion caveat below). Two guard classes, both required: **destination-bounding** (push only to an allowlisted remote behind a secret-scan; apply only approved operation-classes to approved targets; never touch a path outside the action's declared scope) **and payload-bounding (rung-2 finding):** for any egress/push action the executor may emit only bytes whose origin is `{human, corpus-first-party}`, **or** a diff-allowlist bounds the change to non-data-bearing structural forms. The secret-scan is **necessary-not-sufficient** — it catches secrets, not arbitrary attacker-chosen data (PII, internal endpoints, a crafted/encoded blob). **Selection/arrangement bound (rung-3 — the load-bearing addition).** Byte-origin bounding stops attacker *bytes* but NOT an attacker-steered *choice / ordering / encoding of trusted bytes* — untrusted research can still steer *which* trusted bytes leave, a covert channel inside the origin bound. So where an action's output *can* be a fixed projection, the executor emits a **schema-pinned deterministic projection of trusted sources the plan cannot parameterize** (no attacker-chosen row-selection, ordering, or encoding); and the diff-allowlist's "non-data-bearing structural forms" must be a **closed audited grammar, default-deny** — never a builder's guess. Where output genuinely cannot be a fixed projection, the selection channel is **irreducible, bounded to trusted-origin bytes**, and carried to the §8a-Net residual + Pillar 4 — *with the honest caveat that a human gate cannot see selection-steering.* The executor is a small, deterministic, fixture-testable component — **the same trust shape as the TCB itself**, not an attackable LLM.
- **The executor must never write a path that is later executed, and verification sensors run pinned (rung-1b finding).** A "well-typed" plan that writes to an executable sensor / hook / runtime path (e.g. a `deploy/*.py` preflight sensor) would otherwise be run by the host's verify-then-promote loop with host privileges — an exfil path that bypasses tool-grant entirely. So, by construction: executor writes are confined to **non-executed data paths**; the verify-then-promote sensors execute from a **pinned, read-only, trusted location**, never from the mutable workspace the executor just touched; and the writable set is an **allowlist of non-executed data paths, not a blocklist (rung-3)** — every path with checkout/read/install-time execution semantics is denied: not only `.git/`, hooks, and the runtime, but `.gitattributes` filter-drivers, `.gitconfig`, and CI/build manifests (`pyproject.toml`/`package.json` install hooks) that live *outside* `.git/` yet trigger host execution. **And the write-allowlist is strictly DISJOINT from the TCB's own boot-read TRUST-CONTROL surfaces (rung-5 / Gemini-v2 F2 + re-verify)** — the SAFE/path allowlists (§5), the build-generated projection-path *registry* (§4), the first-party path allowlist (§4), the origin register/rows, and the manifest trust-root: each pinned outside the mutable workspace / build-generated / signer-verified, **never executor-writable**, with disjointness extending to the **transitive closure** (any path from which a boot-read surface is derived or regenerated — the rung-2 per-pipeline lesson). This is scoped to trust-CONTROL surfaces, **NOT** "any path read at boot": the executor must still write the origin-bearing **data** (the schema-pinned projection above) that the next boot reads-and-re-tags (never trusted-by-authorship, §4). The execution-semantics denial (above) is anti-RCE; this is anti-privilege-escalation. (The manifest sub-surface was already closed by §4's pinned-trust-root, and the origin register by §9 monotonicity; this generalizes that rule to all trust-control surfaces, and explicitly names origin-register *write*-access.) (This is the concrete content of "guards bound the blast radius regardless of plan content" — the executor-guard completeness the §13 C3 charge demands.)
- **The executor's guards must hold even if Pillar-3 promotion is attacker-controlled (rung-2 KILL fix — the load-bearing correction).** Pillar 3 (verify-then-promote) MAY be an LLM verifier ("a second adversarial agent", redesign brief §44-49) reading untrusted-derived content — so its PASS verdict is **injectable** and is NOT a trust signal the executor may lean on. The earlier wording ("the executor acts only on a *promoted* artifact", with promotion implicitly trusted) **relocated** the old descriptor-attestation FATAL into Pillar-3 promotion rather than dissolving it. Corrected: (i) promotion gates *whether* the executor runs, but the payload/destination guards above must bound harm **regardless of the verdict's honesty**; (ii) the executor **re-checks the promoted artifact's `origin_max` at consume time** (default-deny `unknown`; the artifact + its config are origin-bearing surfaces, §4) — promotion is never the sole trust signal; (iii) a verdict that *must* be trusted (a semantic-correctness call no deterministic guard can make) is a **Pillar-4 human-trigger / cross-vendor** decision, not an in-family LLM PASS. Co-residency ≠ correctness — and correctness (promotion) is **not assumed sound**.
- **Net + honest scope boundary (rung-2 correction).** No LLM co-resides credentials with untrusted-derived content, and the handoff is fully automated (no manual filtering) — the faithful reading of the brief's *"acts on already-decided artifacts, not raw scrape."* **But Pillar 1 alone does NOT make autonomous research→action *push* injection-proof** — that was the v1.2/1.3 over-claim ("trust off the LLM surface entirely"). What Pillar 1 *does* guarantee, and what survived attack (§6), is **runtime co-residency isolation**: a credentialed session cannot be hijacked mid-flight. Making the *push of untrusted-derived content* safe is a **composition with Pillars 2–4** (reversibility + verification-you-can't-fully-trust + a human gate for the irreversible/high-blast-radius slice) and carries an **irreducible residual: LLM semantic verification is injectable, so autonomous research→push is *boundable + reversible + gatable, never injection-proof.*** The executor's payload/destination guards bound the autonomous slice; the residual is **Pillar-4 human-gated** — with a **rung-3 caveat: the human gate is only partial against the selection/arrangement channel** (a human reviewing a diff of genuinely-trusted bytes cannot detect that untrusted research *steered the selection*); the real closure there is the §8a schema-pinned projection, not the gate — **and the autonomy model now encodes this mechanically (rung-4): autonomy §2 adds a `payload_shape` input routing free-selection egress to HUMAN-GATE regardless of blast, so "carried to Pillar 4" is no longer a builder's classification choice.** So this spec scopes the *mechanism*; the push's end-to-end safety is owed jointly to the Pillars-2–4 scoping (not yet done).

### 8b. Relaxation (opt-in, gated — NOT the default)

A typed bridge into a credentialed **LLM** session, for the narrow case where an LLM genuinely must reason over findings *while* credentialed (e.g. interactively operating a live credentialed system). Mechanism: a typed, schema-bounded record with a **finite field vocabulary, machine-validated content classes (controlled-vocab entities, enums, typed scalars, hash references), and NO free-text fields** (so it is **non-injective** — it cannot carry an embeddable imperative; the schema validator, §2, enforces this), and **non-authorizing** (it cannot by itself authorize/clear/mint; it requires corroboration by first-party-trusted evidence or an explicit human decision). Tagged `typed-derived`: co-residency-permitted, never `human`/`corpus`, never authorizing.

This relaxation is **not available by default.** It requires **(a)** the bounded cross-vendor pass (§13 C3) to bless the non-injectivity + corroboration claim, **and (b)** it is a prime **Pillar-4 human-trigger** candidate — the interactive-credentialed-LLM case is exactly where a human trigger may belong. Absent both, §8a is the only path. **If ever revived (rung-4): narrow from "typed" to "opaque and non-executable"** — no policy-significant enums (`override_required`/`publish_ready`-style terms still steer a credentialed LLM), no dereferenceable content handles resolved *inside* the credentialed session, only mechanically-corroborated identifiers a deterministic component resolves *outside* the LLM; anything more has fallen back into co-residency and stays human-triggered. (Rationale and the rejected alternatives are in §14.)

## 9. Mutation & runtime (boot-time immutability primary; runtime best-effort only)

The v1.0 "transactional revoke-before-surface / re-check on every use / fence composite turns" claims are **withdrawn** as primary guarantees — the harness cannot intercept at dispatch (`test-plan:20`, `inner-ring:39`). Replaced by:

- **Boot-time immutability (primary, enforced).** Per §6, a credentialed session cannot ingest untrusted content; a research session has no credentials. Capability does not change mid-session because the *means* to change the trust-relevant state was never granted. This is the whole guarantee, and it is boot-time.
- **Capability mutation by the orchestrator (residual).** If the orchestrator attaches a tool / mounts a secret mid-session, that is a **new grant decision** — modeled as a (cheap) **re-boot of the session envelope** through the TCB, not a runtime patch. There is no "attach without re-grant" path.
- **No-regain.** A session is its boot context; a session that booted untrusted is never re-granted credentials in place. Credentialed work on a new finding is a **fresh action session** booting on the §8 bridge record.
- **Runtime hooks are defense-in-depth only (the DA-10 split).** Where a substrate *does* offer a PreToolUse-style hook, the perimeter egress/secret-scanner hooks remain as a second layer — but the design **does not depend on them**; on a no-hook substrate the guarantee is unchanged because it rests on boot-time absence.
- **Crash/epoch durability (UNRESOLVED — build gate, not yet discharged; rung-2 honesty fix).** The origin register must be on the same append-only, crash-safe, write-ahead path as the thread/session register — **and written atomically with the byte-intake (one transaction, or tag-first); "same log" ≠ atomic (rung-3)** — with recovery proving taint can only **ratchet up or stay** (fail closed to `unknown`); a recovered epoch is a boot and re-runs the grant. **This is asserted as a requirement, NOT proven here** — earlier wording ("carried dependency") read as handled; it is not. It stays **UNRESOLVED pending §13 C5** + two crash fixtures the build must pass before any credentialed re-boot on a recovered epoch: `ingest-written / origin-not-written` and `origin-written / checkpoint-not-written` — whose **pass** condition is the ordering invariant **a byte becomes agent-visible only after its origin row is durable**, not mere desync-detection (rung-3). **Hard gate, normative (rung-4):** no credentialed session may re-boot from a recovered/crashed epoch until that fixture suite passes, and a builder may **not** substitute "same append-only log" for "same atomic commit" — the tag/byte write is one transaction. (Frozen-source gap from the §9 GPT pass; do not read it as dissolved.)
